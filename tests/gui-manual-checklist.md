# GUI 三步迁移向导 — 手测清单(Task 7)

> 对象:`migration/gui/index.html`(单文件页面,零外部资源,由 `gui/server.py` 的 `GET /` 提供)。
> 本清单供人工在真实浏览器中逐条勾选;自动化测试不覆盖页面,页面质量以此清单 + 浏览器冒烟为准。
> 每条含 **前置条件 → 操作 → 预期**;建议按顺序执行(部分条目依赖前一步的状态)。

## 启动方式

```powershell
.venv\Scripts\python -c "import uvicorn; from migration.gui.server import create_app; uvicorn.run(create_app(), host='127.0.0.1', port=8765)"
# 浏览器打开 http://127.0.0.1:8765/
```

> 游戏根目录可直接在页面步①「游戏根目录」输入框中填写并保存(终审 I-1),
> 也可预先在 `.mcmig/config.yaml` 写好 `game_root`(页面打开时自动预填)。

> 推荐的测试数据:两个版本文件夹,源含 `options.txt`(与目标内容不同)、若干 `config/*.toml`(部分带 `.bak`、部分不带)、`mods/` 里比目标多一个 jar、源里再放一个目标未安装 mod 的 config(出 👻 组)与一个顶层未知文件(出 ❓ 组)。

## A. 三步走通

- [ ] **A0 步①游戏根目录设置(终审 I-1)**
  前置:清空 `.mcmig/config.yaml`(或整个删除)后启动页面。
  操作:①观察输入框(应为空,版本列表报「未配置游戏目录」错误);②填写合法游戏根目录(含 `versions/`),点「保存并刷新版本列表」;③再填一个不存在的路径保存。
  预期:①输入框空且 versions 错误条指引到输入框;②保存后版本下拉自动加载出全部版本;③出现三段式错误条「游戏根目录不可用(路径不存在或缺少 versions/ 子目录)」,版本列表保持不变;刷新页面后输入框仍预填②保存的合法路径。

- [ ] **A1 步①版本下拉加载**
  前置:游戏根目录 `versions/` 下有两个以上版本文件夹,`PCL.ini` 有 `Version:` 行。
  操作:打开页面。
  预期:源/目标两个下拉列出全部版本;当前活跃版本选项带「(当前活跃)」后缀;页面顶部显示活跃版本提示行;默认源=活跃版本、目标=另一个版本;「开始生成迁移计划」按钮可点。

- [ ] **A2 同源同目标防呆**
  前置:A1 通过。
  操作:把目标下拉选成与源相同。
  预期:出现「源与目标不能是同一个版本」警告,开始按钮禁用;改回不同版本后警告消失、按钮恢复。

- [ ] **A3 步②计划生成与分组渲染**
  前置:A1 通过。
  操作:点击「开始生成迁移计划」。
  预期:进入②步,先显示「扫描源版本…→扫描目标版本…→生成迁移计划…」阶段文字;随后渲染分组列表,组标题=emoji+名+计数徽章(✅ 必迁 / ✏️ 改过的 config / ❓ 待确认 / 👻 孤儿数据 等);✅/✏️/❓ 组默认展开,👻/⚙️/⛔/📦 组默认折叠,点组头可切换。

- [ ] **A4 步③执行与完成态**
  前置:A3 通过。
  操作:点击「执行迁移」。
  预期:进入③步,阶段显示「正在迁移文件…」,`N / M` 计数与进度条逐文件递增至 `M / M`;结束后显示 summary 五项统计(已复制/内容一致/待确认未勾选/跳过/失败)与绿色「迁移完成」标题;目标版本文件夹里确实出现/更新了计划中的文件。

- [ ] **A5 PCL 提醒全文**
  前置:A4 成功(无失败文件)。
  操作:观察完成态。
  预期:显示「PCL 启动器配置提醒」块,内含 4 行全文(含 `PCL.ini` 的 `Version:` 行与 `PCL\Setup.ini` 的 `LaunchVersionSelect:` 行,路径为本机绝对路径)。

- [ ] **A6 重跑 identical 续传**
  前置:A4 成功后。
  操作:刷新页面,同样参数重新走一遍三步。
  预期:②步计划里已迁过的文件归入「⏭ 一致」等分组;③步完成态「内容一致」计数≈上次「已复制」数,目标文件内容不变(不重复写)。

## B. ❓ 待确认(ASK)勾选传递

  预期:第一遍完成后勾选过的文件出现在目标版本文件夹(打开「运行日志」面板,能看到 `/api/migrate` 之前页面对这些路径的处理结果);summary 的「待确认未勾选」= 未勾选数;第二遍重跑时这些文件归入「⏭ 一致」。

  前置:B1 通过。

  预期:全选时组内所有行被勾选、计数变为「N / N」;取消时全部清零。

## F. 失败清单

- [ ] **F1 失败渲染与复制**
  前置:迁移前用其他程序锁住目标版本里某个将被覆盖的文件(如用记事本打开并输入内容保持句柄,或用 PowerShell 的 `[System.IO.File]::Open` 持有写入句柄)。
  操作:执行迁移。
  预期:失败文件计入 summary「失败」(红色)并出现「失败清单」;清单列出 `路径 — 错误原因`;点「复制失败清单」后剪贴板内容为清单全文;完成标题变为「迁移结束(有 N 个失败)」;此时不显示 PCL 提醒块。

- [ ] **F2 失败后重跑**
  前置:F1。
  操作:关闭占用文件的程序,刷新页面(或点「← 返回重选版本」)重新生成计划后再「执行迁移」。
  预期:重跑不再失败;重新生成的计划中之前成功的文件归入「内容一致」并跳过,不重复复制(直接对旧计划重执行会被「目标状态不一致」阻断——部分执行后的重试路径=重新生成计划,终审修复 I3 口径)。

- [ ] **G2 刷新重开**
  前置:G1。

  预期:回到①步初始状态;重新走流程可用(服务端 job 为内存态,刷新=重走向导,属原型期已知妥协)。

- [ ] **G3 正常收尾不误报断线**
  前置:A4 成功场景。

  预期:done 事件后服务端主动断流,**不**出现断线横幅(页面在收到 done/error 后已主动关闭 EventSource)。

## I. 批次I W1W2 可靠性基座(路径契约 v3/首跑欢迎态/job 上下文定格/取消/journal/退出)

> 对应批次I T1-T6:实例态统一锚定 `<游戏根>/.mcmig/`、首跑欢迎态、job 状态机与取消、
> 跨进程实例锁、write-ahead journal 与中断提示、退出入口守卫。
> 服务端行为已有自动化测试覆盖,此处为真实浏览器下的人工确认。

- [ ] **I1 首跑欢迎态(删全局配置后启动)**
  前置:删除全局配置(源码运行=工作目录 `.mcmig/config.yaml`;绿色 exe=exe 同级 `data/config.toml`);与 A0 的区别:A0 只清空配置验证输入框流程,本条验证**服务本身未配置也能起**(欢迎态契约)。
  操作:按本清单「启动方式」重新起服务并打开页面。
  预期:服务正常启动、页面可打开(不抛错、不白屏);步①输入框为空;版本列表报三段式 422「未配置游戏目录」并指引到输入框;顶部**不**出现中断横幅(`GET /api/jobs/interrupted` 返回空清单);在输入框保存合法游戏根目录后版本下拉正常加载(同 A0-②)。

- [ ] **I2 运行中改游戏根目录,任务不漂移**
  前置:另备一个合法游戏根目录 B(含 `versions/`,可与当前根 A 用同一套测试数据的不同拷贝);迁移(或计划生成)所需的版本文件夹较大,任务需运行数秒。
  操作:标签页 A 点「执行迁移」进入③步;运行期间在标签页 B(或 DevTools 控制台)`POST /api/config` 保存根目录 B;观察 A 的任务直至结束。
  预期:A 的迁移不受影响——进度/文件计数继续增长、无 error 事件、文件仍写入**启动时**定格的原目标版本文件夹(job 上下文在启动时一次性定格,批次I-T1);任务结束后刷新页面,版本下拉与快照/计划读写均来自根目录 B(新配置只影响后续任务)。

- [ ] **I3 取消 migrate 全流程**
  前置:A4 场景,源版本文件较多(取消后仍能看到部分完成计数)。
  操作:执行迁移,运行中点「取消迁移」(按钮随即禁用);再经 DevTools 对同一 job_id 重发一次 `POST /api/jobs/{job_id}/cancel`;等待任务收尾后重新生成计划并再执行一遍。
  预期:按钮变「正在停止…」并显示提示「取消在当前文件完成后生效(安全边界,无半途文件)」;`GET /api/jobs/{id}` 显示 `status:"cancelling"`;当前文件单元完成后任务收尾——done 事件含 `cancelled:true`,完成标题「迁移已取消」,附「已完成 N 个文件,未执行 M 个;如需继续迁移,请返回重新生成计划后再执行(重新生成的计划中已完成文件会按『内容一致』跳过,不会重复复制)」注记,取消按钮退场;重新生成计划后已完成文件全部按「内容一致」跳过、目标内容不变(直接对旧计划重执行会被「目标状态不一致」阻断——终审修复 I3 口径)。DevTools 重发的取消请求仍返回 202(幂等,不产生第二次停止)。

- [ ] **I4 cancel 对 plan 无入口(405)**
  前置:A3 场景,源版本文件夹较大(计划生成需数秒);DevTools 可用。
  操作:点「开始生成迁移计划」;②步运行中观察页面,并用 DevTools 对该 plan job_id 调 `POST /api/jobs/{job_id}/cancel`;再对已结束的 migrate job 与不存在的 job_id 各调一次。
  预期:②步页面**没有**取消按钮(仅 migrate 可取消);对运行中 plan 调 cancel 得 405 三段式「该任务不支持取消」;对已终态(成功/取消/失败)的 job 调 cancel 得 409「任务已结束」;对不存在的 job_id 调 cancel 得 404。

- [ ] **I5 中断 journal 横幅**
  前置:迁移进行中(文件较多,确保 journal 已写入若干意图);与 G1 的区别:G1 看断线横幅,本条看重启后的**中断待核对**横幅。
  操作:Ctrl+C 杀掉服务进程 → 重启服务并打开页面;核对后重新生成计划并执行;最后删除 `<游戏根>/.mcmig/jobs/` 下对应 journal 文件再刷新。
  预期:页面顶部出现中断横幅「检测到上次未完成的迁移(1 个任务、N 项文件状态待核对)…」;`GET /api/jobs/interrupted` 返回该 job 及待核对条目(有意图无完成,呈现为「待核对」而非「未执行」);核对后重新生成计划再执行,已完成文件在新计划中按「内容一致」跳过;横幅持续到人工删除 journal 文件为止(工具不自动清理,提示语义为「请核对」而非「已损坏」)。

- [ ] **I6 退出入口忙碌 409 + 空闲真退出(修复 A5 后两模式接线齐备)**
  前置:迁移(或计划生成)运行中。
  操作:点页面「退出服务」按钮;待任务结束(或迁移取消收尾)后再点一次(两种模式各验一次:默认浏览器模式 `mcmig gui`、窗口模式 `mcmig-gui`)。
  预期:任务运行中点退出得 409 三段式(details 含任务描述)「有任务正在执行——请等待任务完成(迁移任务可先取消)后再退出服务」,服务不退出、页面可继续操作;空闲时点退出返回成功:浏览器模式**服务进程随之退出**(控制台回到命令提示符,页面转为断线重连提示),窗口模式窗口自动关闭、进程退出;**退出服务置位后新任务被 503 拒**(另开一个页面在退出请求后立即提交 plan 可验证,修复 A5 的原子排空)。

## J. 批次I W3 能力收口(两阶段 swap/独立窗口/刷新恢复/断线重连/journal 中断恢复)

> 对应批次I W3 T1-T9:precheck 单点下沉、SSE 终态原子提交+头优先游标、journal 增量化
> 与 dismiss、POSIX flock、页面 Presentation Model+游标四规则、审阅页 IA、swap 两阶段
> API+页面、pywebview 窗口壳。服务端与页面逻辑均有自动化测试覆盖,此处为真实
> 浏览器/真实窗口下的人工确认。

- [ ] **J1 迁移中刷新页面 → 游标恢复**
  前置:源版本文件较多(迁移需运行数十秒),已进入③步执行中。
  操作:任务运行中直接刷新页面(F5),必要时再刷一次;观察恢复后的进度显示。
  预期:刷新后页面回到③步并**续显当前进度**(N / M 计数、阶段文字与刷新前一致),服务端不重扫、不重开任务(DevTools Network 中无新的 `/api/plan` 或 `/api/migrate` 请求,任务进度继续向前);恢复的事件按序号去重,无「从 0 重放」现象。

- [ ] **J2a 网络瞬断(服务进程存活)→ 自动重连**
  前置:迁移执行中,服务进程保持运行;DevTools Network 面板可用。
  操作:①制造网络瞬断(切换系统代理,或禁用再启用网卡),持续数秒后恢复;②恢复并收到若干事件后**再次**断线数秒再恢复;Network 面板观察 EventSource 请求。
  预期:断线期间页面顶部显示「连接中断,正在自动重连…」横幅,恢复后任一新事件到达即清横幅,事件按 seq 去重、界面不重复渲染(计数不跳变回退);再次断线重连时,浏览器以 **Last-Event-ID 请求头**携带最新游标续订(请求 URL 中的旧 `?last_event_id=` 查询参数不再是重放起点),不从旧 query 位置反复重放历史事件(评审 v3 P2-2/白名单⑨)。

- [ ] **J2b 服务进程重启 → journal 中断恢复(与 J2a 两分)**
